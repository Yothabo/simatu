# Admin system

Admin owns authentication, authorization, operational overview, inventory, product and category management, order operations, settings, Admin-specific integrations, tests, assets and its design system.

Customer name and phone are operational order fields only. Do not add customer profiling, segmentation, repeat-customer reporting, lifetime-value metrics, customer comparisons, or marketing analytics.

The existing Admin implementation is migrated in dependency-cohesive batches. Keep current UI, interactions, responsive behaviour and design tokens unchanged during relocation.
